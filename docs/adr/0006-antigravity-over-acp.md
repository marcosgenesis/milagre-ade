# Antigravity runs over the Agent Client Protocol

Antigravity is the third provider, after Claude and Codex; the models it runs are Google's Gemini models. Milagre drives Google's Antigravity agent (`agy_acp_server`) over the Agent Client Protocol: JSON-RPC over stdio. The session code is a generic ACP client; Antigravity supplies its command, environment, permission modes and sign-in. Another ACP agent can be added later as configuration rather than as a new client.

We first chose the Gemini CLI (`gemini --acp`). Since June 2026 Google refuses its sign-in for personal Google accounts ("This client is no longer supported for Gemini Code Assist for individuals") and points them to Antigravity. That left the CLI usable only with Workspace or Code Assist accounts, or API keys. Antigravity works with personal accounts. Its costs are a separate download of about 1 GB, a sign-in that prints its URL on stdout, and upstream hang and cancel bugs that the session must survive.

Milagre installs and updates the agent itself. It downloads the archive listed in the ACP registry, checks its SHA-256 and unpacks it under the host data directory. The registry lists URLs but no hashes, so each release is pinned in `antigravity-install.cjs` with the size and SHA-256 of its archive and the size of each file in it, taken from the downloaded archives. All six platforms of version 1.3.0 are pinned: macOS arm64 and x64, Linux x64 and arm64, Windows x64 and arm64. A platform without a pin is unsupported rather than guessed at. The files differ by platform: Windows archives hold `agy_acp_server.exe` and `localharness_external.exe`, the others `agy_acp_server.par` and `localharness_external`; Linux starts the agent with `--uid=`. The archive is listed and unpacked with `unzip` on macOS and Linux and with the `tar.exe` that Windows ships, and the unpacked sizes are checked. The agent unpacks large files into the temporary directory on each launch, so Milagre points it at a temporary directory it owns and cleans.

A Chat starts with `session/new` and resumes from its saved ID without replaying history as new output. Milagre's instructions and the Chat's linked tools (the `milagre` MCP server) are attached when a session is created. Permission modes map to the agent's modes: ask is `default`, auto is `auto_edit` and full access is `yolo`. `session/request_permission` uses the approval cards. Requests that are really questions use the question card. Stop sends `session/cancel`, and a session that does not confirm the cancel is replaced on the next turn. ACP cannot steer a running turn, so a message sent while Antigravity works becomes the next turn.

Models come from the session's `model` option. The agent reports one model per thinking level, named `<Family> (<Level>)`, such as `Gemini 3.1 Pro (High)`. Milagre groups them into one model per family and offers the levels as that model's efforts, like Claude and Codex. Each family keeps a table from effort to the agent's own model id, because the ids are irregular (`gemini-pro-agent` is Pro at High). A static catalog of the agent's raw options fills in until the first session reports them.

Antigravity's subagents are Milagre subagents, one per child, though ACP says nothing about them: `start_subagent` completes as soon as the children are launched, with no child ids. `antigravity-subagents.cjs` reads them from the transcripts the agent writes under `<GEMINI_HOME>/antigravity-acp/brain/<conversationId>/`, while children are active (fs.watch, with a 500 ms poll behind it). The parent's `invoke_subagent` step gives each child's role (its title) and prompt, the `INVOKE_SUBAGENT` step after it gives their conversation ids, and a `SYSTEM_MESSAGE` from a child is its report, which completes it (or the child's own `send_message` to the parent). A tool call whose id starts with a child's 32-hex conversation id is a row of that child, live. `view_file` calls carry ids like `call_474917` that name nobody; while children run they are left out of the parent's steps and the children's reads come from their transcripts, a second or so late. Stop cancels the children, and so does closing the session. The transcripts are undocumented 1.3.0 internals, so every read is best effort: without them a launch stays a plain step and those reads stay the parent's. A resumed session starts reading the parent's transcript where it ends, so earlier children are never replayed.

Accounts follow ADR-0005. An Antigravity profile is a private directory selected with `GEMINI_HOME`, with file token storage, so profiles never share the macOS keychain entry. Ambient `GEMINI_*`, `GOOGLE_*` and `BROWSER` variables are removed from the agent's environment. Sign-in is Google login: Milagre reads the sign-in URL the agent prints and opens it in the computer's browser. No probe ever starts a sign-in.

Usage comes from Google's Cloud Code backend, not from the ACP agent, which reports none. `antigravity-usage.cjs` reads the profile's `antigravity-acp/acp_token.json` (the agent owns and rewrites it; Milagre never writes it), exchanges its refresh token for an access token in memory, keeps that token per profile until five minutes before it expires, and calls `v1internal:retrieveUserQuotaSummary` with the Antigravity Hub client family in the `User-Agent` (Cloud Code answers no other). The response groups buckets by model family and window; only the Gemini group is shown, as "Gemini 5-hour" and "Gemini weekly" windows with usedPercent `(1 - remainingFraction) * 100`. A bucket that is disabled or has no `remainingFraction` shows no window rather than 100 percent, and an account that only has a weekly bucket shows just that one. The Claude and GPT group is not shown. The endpoint is undocumented, so the parser is defensive, and any failure (no token file, refresh refused, non-200, unreadable body) becomes the ordinary unavailable or error state with a short message, keeping the last good numbers. It never breaks a turn and never puts a token or secret in a message, log or cache. The selected Antigravity Account decides whose quota is read, and the usage cache is partitioned by it like Claude's and Codex's.
