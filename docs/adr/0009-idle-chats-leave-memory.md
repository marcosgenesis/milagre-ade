# Idle Chats leave the daemon's memory

The daemon holds a Chat's messages in memory only while the Chat is in use. A Chat nobody touched for ten minutes, whose turn isn't running or preparing and that no window shows, is unloaded: its messages leave the Project's state, and its rows in `chats.db` (ADR-0007) are the only copy until something needs them. This refines ADR-0007's "the daemon still holds every message in memory". On the large Project #300 and #321 measured, 5.8 MB of the daemon's heap goes once its Chats are idle; with the phone bridge on, 20 MB, because the bridge now holds no messages either.

- **A Chat is loaded or unloaded, never partly.** The state's `messages` holds every message of each loaded Chat, in the Project's order. Which Chats are unloaded travels with each state, tagged on its messages array (`message-store.cjs`); it is never saved or sent.
- **Nothing on disk is lost.** A save writes and deletes rows only for the Chats the state holds; an unloaded Chat's rows stay as they are, unless its Chat is gone from the state, as before. A message's `position` is a sort key now, increasing along the array: a message keeps its position while that keeps the order, and one added or moved takes a position after every row. A details sidecar an unloaded Chat's messages point at is kept by every sweep.
- **Only what is saved leaves.** A sweep unloads a Chat only when `chats.db` holds exactly what memory does: every message saved as it is, none removed since, and no save waiting or running.
- **Whoever needs a Chat names it.** A change to the state lists the Chats whose messages it reads or writes, and those are loaded first; a change that lists none loads every Chat. A change that touches an unloaded Chat without naming it gets the Chat's rows merged back. Reads across Chats (a search, a lookup by id or operation, the chat list, linked reads) read unloaded Chats' rows for that call without loading them.
- **Clients see no difference.** A client that reads messages by Chat never hears an unloaded Chat's messages as removed, nor a loaded one's as new. A client that takes whole states (an older desktop) gets every message, read back from `chats.db`. The phone bridge takes states without messages and asks the host for them on the routes that need them all.
- **Opening is unchanged.** A Project still reads every message when it opens; the sweep unloads the idle ones afterwards. `MILAGRE_LAZY_MESSAGES=0` keeps every message in memory, as before.
- **Considered and rejected:** unloading the payload of each message but keeping a stub in the array (every reader of a body would read an empty one, and a save could write the stub over the row), and a full message store behind every reader at once (about 80 readers changed in one step, where naming the Chats at each writer and keeping the array changes a few dozen).
