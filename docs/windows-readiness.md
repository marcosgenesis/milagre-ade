# Windows readiness

Scope: the existing x64 Windows runtime and per-user NSIS installer. Windows ARM64, a public signed release, WinGet publication, and new update services are outside this change. Git and a supported, signed-in agent CLI remain prerequisites; Electron supplies the daemon's Node runtime.

## Diagnosed failures

Baseline `main`: `6151a5f120fdd6af1b3e946aaf0591e53dae8c18` (checked October 10, 2026). Previous `e3768cd` passed both Windows jobs. The only intervening commit is #412's phone selection persistence; timing-sensitive failures alone do not establish it as the cause.

- [#414](https://github.com/the-ptf/milagre-ade/issues/414): `poll({ fresh: true })` silently returned during an in-flight scheduled poll. A Windows process query can outlast the polling interval, so `stopPort` could return with an older listener snapshot. A deterministic overlap test reproduces this without Windows timing; forced reads now wait and re-read. Refused identity stops return false, and walking command ancestry stops below a Terminal shell.
- [#413](https://github.com/the-ptf/milagre-ade/issues/413): the installed-check step actually failed during its **source** desktop phase, before the installed executable was checked. Accepted optional PR reads can spend 30 seconds on a batch and then 15 seconds on a fallback, while shutdown drains accepted work and the client deadline is 30 seconds. Closing the runtime now aborts its optional batched reader and prevents fallback/new reads. Tests cover a held read, a real child process, and runtime shutdown; accepted writes and failed-save retry remain covered by the existing tests. Native CI must confirm this explains the observed Windows timeout.
- NSIS's default process check may forcibly terminate processes running from the installation directory. Since the daemon survives normal desktop quit, it needs an authenticated stop before that check. The new hook runs an installer-owned helper through the previous installed Electron in Node mode, using that installation's client; it does not require a new flag in the previous app. Authentication, save, connection and ownership errors block replacement. It never enumerates or kills PIDs itself.

## Verification plan

1. Run the root typecheck, lint and complete unit suite; focused port, PR-reader, runtime, installer-stop and workflow regressions must pass. Record environment failures as failures, not Windows certification.
2. Existing CI runs native Windows Git, pipe/ACL, ownership and process tests on the final PR commit.
3. Add `preview:windows` to opt into **Windows readiness**, or dispatch that workflow. It uses a standard `windows-latest` runner, read-only repository permission and unsigned `--publish never` packaging. It does not call release/deploy, produce signing credentials, change host security settings or bypass Electron's sandbox. Screenshots are temporary Actions evidence, retained seven days; no installers are uploaded for public distribution.
4. The native installer check exercises source/installed desktop, the packaged PTY, blocked replacement, live-host same-version reinstall, live-host uninstall and saved data. Metadata generation must also pass.

## Limits before declaring Windows ready

A green Linux check does not certify Windows. Native CI covers the runner's Windows Server/x64 environment, not a Windows 10/11 consumer-device matrix. Live signed-in provider turns, production Authenticode/SmartScreen behavior, a signed version-to-version update and feed promotion still need real verification; this task does not publish or provision credentials. NSIS uses the default `%APPDATA%\Milagre` profile; a manually selected custom-profile daemon must be stopped separately before changing its installation. Upgrades from legacy builds without the daemon client are not certified by same-version reinstall.

Current verification results and final commit links are reported in the draft PR. The repository's older distribution evidence describes earlier commits and does not supersede these gates.
